## Backend changes

- `routes/web.php` — 3 new routes in the existing guest
  `throttle:60,1` group: `meets/{meet}/sports` (`public.sports`),
  `meets/{meet}/news` (`public.news`), `meets/{meet}/contact`
  (`public.contact`) — same `whereNumber('meet')` constraint as every
  existing meet-scoped public route.
- `app/Http/Controllers/PortalController.php`:
  - `sports(int $meet)` — resolves `$meet->events()->with('sport:id,
    name')->get()->groupBy('sport_id')`, maps each group to
    `{id, name, event_count}`, sorted by name. One query, no N+1 (the
    `sport` relation is eager-loaded before grouping).
  - `news(int $meet)` — `Announcement::published()->where('meet_id',
    $meet->id)->orderByDesc('published_at')->orderByDesc('id')
    ->paginate(10)->withQueryString()->through(...)`, mapping to
    `{id, title, body, meet, published_at}` — the same field shape the
    home page's `publishedAnnouncements()` already produces, so the
    shared `PublicAnnouncements` component needs no change.
  - `contact(int $meet)` — returns `{'meet' => $this->meetSummary($meet)}`
    only; zero new query beyond the standard `Meet::published()`
    lookup.
  - All three resolve `Meet::query()->published()->findOrFail($meet)` —
    unpublished meets 404, identical to every existing public action.

## Privacy verification

- All three actions resolve through `Meet::published()` — unpublished
  meets 404, proven by a dedicated test in each new test file.
- **Sports**: exposes only `id`/`name`/`event_count` — no `active` flag,
  no timestamps, nothing beyond what a card grid needs. Verified by a
  dedicated `missing()` test.
- **News**: exposes only `id`/`title`/`body`/`meet`/`published_at` — no
  `is_published`, `created_by`, or `meet_id`; unpublished announcements
  and other meets'/general announcements are structurally excluded by
  the query, proven by a dedicated test creating all four variants in
  one assertion.
- **Contact**: exposes only `meetSummary()`'s existing 7 fields — no
  `contact_email`/`contact_phone`/`office_address`/`status`. A
  dedicated test asserts `missing()` on all four to keep the "no
  invented office-contact content" decision enforced by the suite, not
  just documented in prose.
