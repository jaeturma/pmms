## Files changed

- `resources/css/app.css` — three new `@theme` animation entries reading
  the existing motion tokens: `--animate-card-in` (fade + 8px rise, for
  card entrances and the "tab transition" equivalent), `--animate-score-
  pop` (a brief scale-to-1.08-and-back, for score-change emphasis), and
  `--animate-winner-in` (fade + scale-bounce-in, for the winner
  celebration) — each with its own `@keyframes`, all inheriting the
  existing global `prefers-reduced-motion: reduce` reset automatically.
- `resources/js/components/live-score-display.tsx` — `TeamPanel`'s score
  `<p>` gained `key={score}` (the same remount-key technique
  `RunningClock`/`LastUpdated` already use in this file) plus
  `animate-score-pop`, so it replays the pop on every real score change.
- `resources/js/components/rank-badge.tsx` — new optional
  `celebrate?: boolean` prop; adds `animate-winner-in` only when
  `celebrate && position === 1`. The caller opts in explicitly rather
  than the component guessing from context, so it only plays where the
  caller can vouch the data is validated/finalized.
- `resources/js/components/public-loading-skeleton.tsx` — new,
  `PublicLoadingSkeleton`, wraps the existing `Skeleton` primitive in a
  generic `role="status"` block with an `sr-only` "Loading…" label.
- `resources/js/pages/public/home.tsx` — `animate-card-in` (staggered
  0/80/160ms) on the three highlights cards; `animate-card-in`
  (staggered, capped at 12 items) on the competing-municipalities grid
  tiles; the "Latest official result" card's `RankBadge` now passes
  `celebrate`.
- `resources/js/pages/public/meet.tsx` — the day-dependent schedule
  content is now wrapped in a `key={selectedDay}` div with
  `animate-card-in`, so switching days replays the entrance.
- `resources/js/pages/public/athletics.tsx` — the same day-switch
  wrapper around its per-day event list.
- `resources/js/pages/public/results.tsx` — new `loading` state
  (`onStart`/`onFinish` on the sport-filter `router.get`), showing
  `PublicLoadingSkeleton` while a filtered visit is in flight; plain rank
  numerals replaced with `RankBadge celebrate` (this page is validated-
  only data, per its own scope); `animate-card-in` on the results list.
- `resources/js/pages/public/tally.tsx` — same `loading`/
  `PublicLoadingSkeleton` pattern on both filters; `animate-card-in` on
  the main content block (stat cards through school standings).
- `docs/ui-ux/premium-design-system.md` — new "WP-08.5-06" section

## Motion

All three new animations read `--ease-premium`/`--duration-base|slow`
per WP-08.5-02's own hand-off instruction, rather than inventing new
timing values. None are a flash or a bounce loop — `card-in` and
`winner-in` are one-time entrances (`animation-fill-mode: both`,
starting and ending in a stable state, no flicker), `score-pop` is a
single brief scale, consistent with the motion guidelines' "avoid
flashing" rule already followed by `--animate-pulse-live`.

## Responsive behavior

No breakpoint-specific behavior was introduced or changed — every new
animation is a CSS-only transform/opacity effect applied via existing
responsive layouts, unaffected by viewport width.

## Large-display behavior

No kiosk/TV route exists yet (WP-08.5-07's scope, unchanged). The new
animations are all subtle, professional-broadcast-appropriate motion
(not flashy), consistent with what a future large-display mode built on
the same components would inherit for free.

## Accessibility

- Every new animation automatically respects `prefers-reduced-motion`
  via the existing global reset (WP-08.5-02) — confirmed by inspection,
  not assumed: the reset forces `animation-duration` to near-zero on
  every element, and because `card-in`/`winner-in` use
  `animation-fill-mode: both`, the element still ends in its final
  (visible, correctly positioned) state even when the animation itself
  is imperceptibly short — the same mechanism `--animate-pulse-live`
  already relies on, not a new pattern.
- `RankBadge`'s new `celebrate` motion doesn't change its existing
  accessible behavior — the crown icon is still `aria-hidden`, the
  visible rank/color still carries the meaning.
- `PublicLoadingSkeleton` uses `role="status"` (implicitly
  `aria-live="polite"`, same convention the existing disconnected-state
  banner in `live-score-display.tsx` already uses) plus an `sr-only`
  "Loading…" label, since the skeleton bars themselves carry no
  accessible content.
- No heading order, focus-management, or form-label behavior was
  touched.
