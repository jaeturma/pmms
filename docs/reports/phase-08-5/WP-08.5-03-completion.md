# WP-08.5-03 — Completion Report

Public Portal Hero and Event Branding. Status: **done**.

## Repository findings

The portal home (`public/home.tsx`, fed by `PortalController::home()`) was
the natural target for this WP's Objective — it already carries
`PublicPageHero` (WP-08-07, re-themed onto `.bg-premium-hero` by
WP-08.5-02) plus quick-action buttons, the competing-municipalities grid,
and an announcement list, but `home()` only ever passed `meet`,
`municipalities`, and `announcements`. Checked against the Objective's
explicit list — "live-now entry, current leaders, upcoming events, latest
official result, announcement strip" — four of five already existed
elsewhere in the codebase and just weren't wired into the home page:
`liveMatches` (`PortalController::liveMatches()`, already built for
`public/meet.tsx`), a "top by points" leaderboard (`TopByPointsCard`,
already built for `public/tally.tsx`), and the announcement strip itself
(`PublicAnnouncements`, already present on this page). Only "upcoming
events" and "latest official result" had no existing query or component
anywhere in the portal — both needed new, small, real-data queries.

No `Tabs` primitive was added — WP-08.5-02's completion report flagged
this page as a candidate if hero/branding work touched navigation, but
this WP didn't touch `PublicMeetNav` (the home page doesn't render it;
only the per-meet pages do), so that candidate didn't apply here and
stays open for whichever WP does touch it.

## Files changed

- `app/Http/Controllers/PortalController.php` — `home()` now injects
  `MedalTallyService` and returns three new props plus one reused one:
  - `liveMatches` — reuses the existing private `liveMatches()` method
    verbatim (no duplicate query logic).
  - `currentLeaders` — new private `currentLeaders()`: top 3 municipalities
    by points, via `MedalTallyService::standings()`, the same weighting
    `tally()`'s "Top by points" widget already uses on the full tally page.
  - `upcomingEvents` — new private `upcomingEvents()`: the next 5 schedule
    slots that haven't finished yet (today's remaining slots plus future
    days), earliest first.
  - `latestResult` — new private `latestResult()`: the most recently
    validated result (by `validated_at`), top 3 placements only, or `null`
    before any result is validated.
- `resources/js/components/public-live-matches.tsx` — new. Extracted the
  "Live now" list markup from `public/meet.tsx` (WP-08.5-02's consumer)
  into a shared `PublicLiveMatches` component so the home page's second
  use doesn't duplicate it — same extraction pattern the codebase already
  uses (`TopByPointsCard`'s own doc comment: "extracted on its second
  use").
- `resources/js/pages/public/meet.tsx` — now imports and renders
  `PublicLiveMatches` instead of its inline "Live now" JSX; the local
  `LiveMatch` type and unused `Radio`/`LiveBadge` imports were removed.
  Zero visual change on this page — same markup, now shared.
- `resources/js/pages/public/home.tsx` — adds, after the existing
  announcement strip: a `PublicLiveMatches` section (hidden when nothing
  is live, same as the meet page), then a three-card "highlights" row
  (`TopByPointsCard` for current leaders, a new "Upcoming events" card,
  a new "Latest official result" card reusing `RankBadge`), above the
  existing competing-municipalities grid.
- `docs/ui-ux/premium-design-system.md` — appended a short note closing
  WP-08.5-02's open "spacing" flag: the home page's existing `gap-8`
  page-level spacing already satisfies the "premium spacious" guidance
  and needed no change; the new highlights row's `gap-4` is ordinary
  card-gutter spacing, not the page-section gap that note was about.
- `docs/phases/phase-08-5-premium-sports-experience/CHECKLIST.md` —
  corrected WP-08.5-01 and WP-08.5-02 to checked (they were already done,
  per their own completion reports, but the checklist had never been
  updated) and checked off WP-08.5-03.
- `docs/reports/phase-08-5/WP-08.5-03-completion.md` — new, this file.

No migration, policy, or authorization rule was touched. No test fixture
was touched.

  events/latest result; everything below (municipalities grid) unchanged.

## Responsive behavior

The new highlights row is `grid gap-4 lg:grid-cols-3` — single column
through tablet, three columns from `lg:` (1024px) up, consistent with the
project's existing WP-08-14 convention of not splitting narrower
multi-card rows until there's room. Verified narrow-width safety by
inspection: no fixed widths, all text wraps or truncates
(`min-w-0 truncate` on the latest-result athlete name, matching the
existing pattern elsewhere in the codebase).

## Large-display behavior

No kiosk/TV route exists yet (WP-08.5-07's scope, unchanged this WP). The
home page's new sections carry no private data and no operator controls,
same boundary as every existing public page.

## Accessibility

- `PublicLiveMatches` is the same markup previously inline in `meet.tsx`
  (already accessible — `LiveBadge`'s pulse is `aria-hidden`), just moved,
  so no accessibility behavior changed there.
- The new "Upcoming events" and "Latest official result" cards use
  `aria-hidden="true"` on their decorative `CalendarClock`/`RankBadge`
  icons, consistent with WP-08.5-02's rule (icon reinforces a visible
  text value, doesn't carry new meaning) and WP-08-15's accessibility
  review pattern (decorative icons next to their own label get
  `aria-hidden`).
- No heading order, focus-management, or form-label behavior was touched.
