# WP-08.5-05 — Completion Report

Premium Mobile Sports Experience. Status: **done**.

## Repository findings

Checked the Objective's checklist ("bottom navigation, mobile medal
tally, rankings, schedule, results, compact scoreboards, touch-friendly
filters, safe areas, reduced density, and fast loading") against the
actual mobile chrome instead of rebuilding it. Most items were already
real, built across earlier phases: the fixed bottom tab bar with iOS
safe-area padding (WP-08-09), the collapsed 8-row ranking preview on
`public/tally.tsx` (WP-08-09), the full responsive-breakpoint pass
across every public page (WP-08-14), and `gap-6`+ page-level spacing on
every public page (already satisfying WP-08.5-02's "reduced density"
guidance, not just on the home page WP-08.5-03 touched).

Two real gaps, found by reading the actual mobile-relevant components
rather than trusting the checklist wording alone:

1. **Compact scoreboards** — `.text-score`/`.text-score-lg`
   (`resources/css/app.css`) were a flat `text-6xl`/`text-9xl` regardless
   of viewport width. The live scoreboard's `grid-cols-[1fr_auto_1fr]`
   divides the viewport three ways; a three-digit score at 60px/128px
   font-size overflows a phone-width (~110px) team panel. A real,
   concrete overflow risk, not a hypothetical one — basketball scores
   routinely reach 3 digits.
2. **Mobile live indicators** — WP-08.5-02's own completion report
   explicitly named `public-layout.tsx`'s header "Live now" button and
   `PublicBottomNav`'s "Live" tab as left for "whichever later WP (05
   mobile, 09 polish) actually reworks those specific components." This
   WP is that WP for the bottom nav (a mobile-only component) and the
   header (visible at every width, including mobile).

## Files changed

- `resources/css/app.css` — `.text-score` is now
  `text-4xl font-bold tabular-nums sm:text-6xl` (was a flat `text-6xl`);
  `.text-score-lg` is now `text-6xl font-bold tabular-nums sm:text-9xl`
  (was a flat `text-9xl`). Both restore their original size at `sm:`
  (640px) and up — tablet, desktop, and broadcast/large-display views are
  visually unchanged; only sub-640px phones get the smaller step.
- `resources/js/components/live-score-display.tsx` — `CenterPanel`'s
  fullscreen running-clock size classes changed from a flat
  `fullscreen ? 'text-6xl' : 'text-3xl'` to
  `fullscreen ? 'text-4xl sm:text-6xl' : 'text-3xl'`, matching the same
  breakpoint — this `auto`-width center column would otherwise squeeze
  the two (now-fixed) score panels even further on a phone.
- `resources/js/components/public-bottom-nav.tsx` — `BottomNavItem`
  gained an optional `live?: boolean`; when set, the tab's icon gets a
  small `aria-hidden` pulsing dot overlay (reuses the existing
  `animate-pulse-live` keyframe from WP-08.5-02, no new animation).
- `resources/js/layouts/public-layout.tsx` — the "Live" bottom-nav item
  now passes `live: true`. The header's "Live now" button (visible at
  every viewport width) now renders a single `LiveBadge` pill
  (`"Live now · {count}"`) instead of a static `Radio` icon + text +
  count `Badge` combo; the now-unused `Badge` import was removed
  (`Radio` is still used for the bottom-nav icon).
- `docs/public-portal.md` — extended the "Accepted deviations" note:
  re-confirmed the public filter `Select` triggers (36px,
  `data-[size=default]`) are already above the app's accepted 32px
  touch-target baseline, so "touch-friendly filters" needed no change.
- `docs/ui-ux/premium-design-system.md` — new "WP-08.5-05" section
  recording both closed gaps and everything checked-and-found-sound.
- `docs/phases/phase-08-5-premium-sports-experience/CHECKLIST.md` —
  checked off WP-08.5-05.
- `docs/reports/phase-08-5/WP-08.5-05-completion.md` — new, this file.

No route, controller, model, migration, policy, or test fixture was
touched — this WP is frontend-only.

## Visual / backend / frontend changes

- On phones (<640px), a live scoreboard's team scores and (in
  full-screen mode) running clock render at a smaller, non-overflowing
  size; tablet/desktop/broadcast views are pixel-identical to before
  (the `sm:` step restores the original size).
- The public portal header's "Live now" indicator is now the same
  pulsing red pill used everywhere else "live" is shown in the app,
  instead of its own one-off static combo — visible at every viewport
  width, not mobile-only.
- The bottom tab bar's "Live" tab (mobile only, <640px) now shows a
  small pulsing dot on its icon, matching the same visual language.
- Backend: untouched. No PHP file was modified in this WP.

## Reusable components

- `BottomNavItem`'s new `live?: boolean` field is a small, general
  extension to an existing shared component — available to any future
  bottom-nav item that needs the same "something is live" dot without
  a fifth ad hoc treatment.

## Motion

The bottom-nav dot reuses `--animate-pulse-live` (WP-08.5-02) rather
than introducing a second pulse animation — automatically respects
`prefers-reduced-motion` via the existing global reset, no new guard
needed. No other motion was added or changed this WP.

## Responsive behavior

This WP's core focus. Both scoreboard typography fixes are themselves
the responsive-behavior deliverable — verified by checking the actual
column-width arithmetic (a ~110px-wide team panel at `text-6xl` versus
`text-4xl`) rather than assuming it was fine. The header/bottom-nav live
indicator changes render correctly at every breakpoint already exercised
by their existing usage sites (no new breakpoint-specific behavior was
introduced by those two).

## Large-display behavior

The `sm:` step on `.text-score`/`.text-score-lg` and the clock size
means tablet, desktop, and any future large-display/kiosk mode
(WP-08.5-07) built on the same fullscreen pattern keeps the original,
larger sizing — this WP only affects the sub-640px phone range. No
kiosk/TV route exists yet (unchanged, still WP-08.5-07's scope). Large-
display views still carry zero private data and zero operator controls
— no prop or route was added that could weaken that boundary.

## Accessibility

- The bottom-nav pulsing dot is `aria-hidden="true"`; the tab's own
  visible "Live" label already carries the meaning, so nothing is
  announced twice — same rule every other live indicator in the app
  already follows.
- `LiveBadge`'s existing accessible behavior (aria-hidden dot, visible
  text carries meaning) is unchanged by its new header call site.
- No heading order, focus-management, or form-label behavior was
  touched.
